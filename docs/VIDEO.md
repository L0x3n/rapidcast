## Narration draft

Chat has the ideas. RapidCast gives those ideas a place in the show.

This is a desktop Twitch studio with interactive overlays, four scenes and optional AI. Its widgets can also run as transparent browser sources in OBS.

A viewer suggests a widget with a chat command. The idea is screened and waits for the streamer. I can reject it, edit it, or approve it. RapidCast asks the configured model to write a small canvas widget, checks its source and runs an isolated draw test. Only then can the approved result be published. The program credits the viewer who supplied the idea.

Generated widgets run in separate Workers with no network or credentials. Here a deliberately broken widget is paused while the local recording continues. The runtime watchdog stays active after the initial test.

The setup guide helps choose sources, test the current output load and preview a style. Local encoding results and Twitch delivery are different checks. The streaming engine is still labeled beta, and OBS remains available.

Stats records the session locally. Twitch events and simulator tests stay separate. These markers show confirmed widget triggers. The table compares two minutes before and after complete trigger windows, with missing data and overlapping windows called out. It shows association, not proof that a widget caused a change. An optional AI report works from anonymous totals, and the measured Markdown report remains available without AI.

Overlay packs carry the four scenes, code, parameters, images and credits. The recipient reviews the contents and runs the same sandbox tests before replacing their layout. They choose their own capture devices.

Linus directed the project, and the application, tests and release workflow were built with Codex in one continuous chat. Native Electron and FFmpeg checks complement the automated tests.

RapidCast makes chat part of building the stream, while the streamer keeps control of what goes live.
