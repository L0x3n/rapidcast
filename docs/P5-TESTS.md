# P5: six-step setup and Repair

## Automated verification

Run sequentially after `npm ci`:

```powershell
npm test
npm run build
npm run smoke:setup
npm run smoke:widgets
npm run smoke:ai
npm run check:rtmp
```

The fresh-profile native check traverses the local route using actual Electron, the compositor, Workers, safeStorage and bundled FFmpeg. It lists devices without opening them, explicitly selects only the test app's own window long enough to verify capture frames, then switches to a widgets-only synthetic program. Camera, microphone and Windows playback remain off. A marked fixed-response HTTP endpoint supplies style JSON; no real model or Twitch is contacted.

The check verifies six steps/first-run opening, local route choice, no capture from discovery, own-window frames, cancellation without a partial approved sample, locked program/scene changes, rejection of private/public Twitch actions without the required evidence, invalid theme rejection, four previews before Apply, a full 15-second minimized local sample, one-click recommendation, actual decoded 1280×720 H.264/AAC, persisted local completion, the Ready recording action and Repair preserving settings while invalidating stale approvals. Screenshots are visually inspected when capture succeeds.

Windows did not initially enumerate the background test app window. The native harness restores/shows/focuses its own window and refreshes choices; it matches the native window handle and never falls back to another open RapidCast window. This is a test harness accommodation, not evidence about every game/window capture backend.

Artifacts: ignored `out/setup-smoke/report.json`, `style-preview.png`, `ready-local.png` and `720p-setup-test.mp4`. `localSetupMs` measures an automated local route with a fixed-response style model. It is not a human usability benchmark or real Twitch onboarding acceptance. Reports retain configuration signatures for reproducibility, not credentials.

Vitest covers migration/scaling, FIFO warning classification, recommendation bounds, no untested 60 fps or invented upload capacity, local/private distinction, account/age/program/widget/encoder binding, data-only theme validation/contrast, scene/source preservation, full test duration, cancellation/lock cleanup and readiness requiring live tracks plus a private test/user Inspector review before public output. Runtime source-health capabilities distinguish a retained last image from a live capture and an open audio track from a selected device name.

## Manual acceptance

1. **Fresh profile and login.** Rebuild/start a fresh profile without deleting an existing user's app data. Confirm Setup opens and progress resumes after reopening. Choose Twitch, enter the public Client ID if absent, authorize the shown code in your own browser and wait for chat/events. Time the human flow from Welcome. Local recording can skip Twitch, but must show it as untested. Never put tokens/keys in chat.
2. **Real devices.** Enter Devices, verify displays/windows/cameras/mics are listed, select your intended game/window, optional camera/mic and system audio, then Apply. Inspect actual pictures and meters. Record/play back speech and game sound before confirming the picture/audio checks. Test None, denied permission, an unplugged device and an ended capture: failed/unopened tracks must not show ready. Device IDs/labels and quality depend on Windows privacy and drivers.
3. **Real performance.** Select Live and run the 15-second private Twitch test. Confirm it is not public, ends automatically and uses the chosen program/audio. Review actual delivery in Twitch Inspector before checking its review box. Minimize/use your fullscreen game. Apply the recommendation and retest if output got heavier or the program changed. Cancel an in-progress test, try changing scenes/params/output settings, and confirm no partial approval or competing output remains. Complete P2's separate ten-minute/fullscreen-game and real audio-sync checks; 15 seconds alone is insufficient.
4. **Style and review.** With your real AI model, describe your stream; without AI use a preset. Inspect all four layout previews, then Apply and inspect actual output. Check colors/fonts/layout and preservation of custom widget code/capture IDs. The previews use source placeholders, not camera/game pixels. Recheck sources/performance after styling. Verify mismatched/expired results, another Twitch account and a local-only sample cannot satisfy the Twitch path. Click public Go Live only when intentionally ready; Start local recording must stay local.
5. **Repair and timing.** Save successful setup and reopen; a completed profile starts in Live. Run Recheck setup with output stopped. Verify it retains settings/layers/credentials, reports failed diagnostics honestly and requires another performance test. A saved Twitch login reconnects; a configured model gets a small completion request. Test cancellation and a stopped model server. Record human total time and remaining issues in PLAN, aiming for under five minutes with working accounts/devices. Until that happens, real Twitch five-minute acceptance remains unverified.

## Implementation and evidence limits

- The six saved steps are Welcome, Twitch, Devices, Performance, Style, Ready. `setup.json` stores progress, explicit user checks, applied theme and short benchmark evidence. Credentials remain in their existing encrypted files. Completion is setup history; current readiness is recomputed from current program/device/widget state.
- Discovery enumerates without capture. Apply replaces display/camera layers in Live (reusing existing geometry where possible), updates global audio, selects Live and starts preview. Other scene/layer types are kept. The user can choose no capture/audio. Active camera/display tracks and selected microphone/desktop tracks must report live capabilities; the user still confirms picture correctness, audible sound and mute/playback.
- Performance uses 15 seconds after encoded output starts, with startup timeout and cancellation. It measures compositor slot deltas, encoded frames/drops, peak input queue and latched output/recovery warnings. Stability requires enough frame progress, under 1% missed slots, no encoder drops/output issues and queue below 8 MB. It is not an upload speed test and has no measured remote-ingestion loss metric. Twitch mode always requests the host's private target; it cannot be replaced by a renderer URL. Inspector acknowledgment is explicitly user-reported.
- Evidence expires after 30 minutes and is tied to scene/audio settings, widget params/disabled state, tested resolution/FPS/bitrate, actual encoder and Twitch account where applicable. Lighter matching output can retain a stable result. Changed/heavier output, different scenes/params, another channel or a different current encoder requires review/retest. Failed/unopened tracks block readiness until live again; recheck the actual picture/sound after a device restart or a Windows default-device change. The test uses Live as a representative capture scene; it does not benchmark all four scenes or a long game session.
- Recommendations are conservative starting heuristics informed by single-encode profiles: 720p30/3000, 1080p30/4500, 720p60/4500 and 1080p60/6000 kbps. A recommendation never invents spare upload bandwidth or upgrades untested FPS. Unstable results prefer 720p30 and stable CPU results stay at 30 fps; lowering encoded resolution still leaves the compositor at 1080p, so reduce source/widget load too. A tested bitrate below 3000 recommends retesting 3000 rather than claiming it was covered. Enhanced Broadcasting/2k is outside this app's single H.264 pipeline.
- Program/test leases block competing output starts, scene/program/param changes and retain emergency Stop. Locks release on failure/cancel. Setup never stops an already-running user's output to start a test/Repair. Repair prevents new output while diagnostics are in progress and waits for the current diagnostic on cancellation; it does not silently run another private test or wipe credentials/settings. It checks storage, encoder, enumeration, loopback overlay, a saved Twitch connection and configured AI text completion. A model check may use provider credit.
- AI style generation uses the existing main-process client/key boundary and accepts JSON data only. Supported fonts: Segoe UI, Consolas, Georgia; layouts: chat-left/chat-right; colors: #RRGGBB with a 4.5 contrast floor for accent/background; four bounded plain-text titles. No code, URLs, arbitrary CSS/fonts or privileged evaluation is accepted. Presets work without AI. Applying updates managed background/title layers and builtin accents/fonts/Live layout; it does not rewrite custom widget code. Four SVG layout previews are illustrative and labeled accordingly.
- Readiness distinguishes local from Twitch. It includes running preview, live selected tracks, explicit user picture/audio checks, active rendered widgets, current matching test and (for Twitch) connected account plus user Inspector review. Public output requires an explicit Go Live action. Engine beta and the OBS fallback remain visible. Short tests do not complete the original real-device/game/Twitch acceptance.

Primary references: [Twitch broadcasting profiles](https://help.twitch.tv/s/article/broadcasting-guidelines?language=en_US) and [Twitch Inspector](https://help.twitch.tv/s/article/guide-to-using-twitch-inspector); [Electron capture source IDs](https://www.electronjs.org/docs/latest/api/structures/desktop-capturer-source) and [permission handling](https://www.electronjs.org/docs/latest/api/session); [FFmpeg scale filter](https://ffmpeg.org/ffmpeg-filters.html#scale). AI HTTP schema follows the already-verified [OpenAI Chat Completions reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create). Recommendations are RapidCast heuristics, not a Twitch health certification.
